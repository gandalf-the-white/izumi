#+title: Let’s let them choose the encryption
* Introduction
However, I propose an architecture in which AI plays a genuine role in the negotiation process, but never has the final say on security. Agent Rig recommends a cryptographic suite from amongst those authorized; a deterministic CryptoPolicyEngine verifies the proposal, and the Rust cryptographic engine executes only known, pre-registered protocols.

* Why use AI?
** Imagine
We can present condition such as
#+begin_src emacs-lisp
Information             Example
-----------------------------------------
Capabilities            AES-GCM, ChaCha
CPU                     AES-NI available
Environment             Kubernetes / Edge
Policy                  AES mandatory
Performance             Latency priority
Compliance              Authorised suites
Security level          Standard / High
System Load             High CPU
Peer Characteristics    ARM/x86
Application Constraints Low latency
History                 Previous failures
#+end_src
With these information, AI recommend the most appropriate suite. AI is therefore becoming a negotiation adviser, not a cryptographic engine.
We can imagine a server collecting information and send its to the agent, such as an /Oracle/ accompanied by a /RAG/.
